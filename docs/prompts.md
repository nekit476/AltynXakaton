## S0 · Каркас проекта (04.11, A, Claude Code)

> Так давай проект инициализируем и создадим, прочитай все мд файлы внутри папки, напиши папку проект МД, надо проект инициализировать, чтобы любой чел одной командой поднимал и создавал себе виртуальное окружение под проект. Плюс все интеграции, плюс докеры и тд.
> То есть нужно, чтобы ты проработал каркас приложения, поднял локал хост, создал команду для установки всех зависимостей в окружение.
> Далее мы поднимем образ базы данных в докер контейнере и будем к ней обращаться как к удаленной, чтобы локально все не ставили себе. Пока что путсть локальной будет у меня, но в скором времени она переедет на удаленную репу, имей это ввиду и закладывай в код. Плюс нужно раздельить все на 4 модуля: модуль тестов, модуль для первого второго и третьего участника

Результат: [ТЗ](tz/S0_skeleton_tz.md), [план](plans/S0_skeleton_plan.md), [PROJECT.md](../PROJECT.md).

**Что агент нашёл сам и учёл:**
- На машине не было uv, Docker и make, а Python стоял 3.11 вместо 3.13. Решение: установку берёт на себя uv, команды вместо make — poe.
- Порт 5432 занят системным PostgreSQL 17. PostgreSQL в Docker переехал на 5433.
- Общая база на троих сломала бы чужие миграции и тестовые базы. Решение: один сервер, у каждого своя база.

**Что пришлось исправлять по ходу:**
- Самопроверка сторожа импортов упала: на одну строку `from domain.org.models import Group` он сообщал о двух нарушениях. Теперь отчёт идёт по строкам импорта, с номером строки.
- В poe строки внутри `sequence` по умолчанию считаются ссылками на задачи. Задачи `lint`, `fmt` и `check` не запускались, пока им не указали `default_item_type = "cmd"`.

**Граница ответственности:** агент написал код, тесты и документы и проверил их запуском. Решения о разделении на модули и о БД в Docker «как удалённой» принял человек. Docker Desktop ставит человек, и проверка `docker compose` остаётся за ним.
