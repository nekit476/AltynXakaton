## 1. Три роли

Монолит на Django режется **по слоям**. Контракт между B и C — сигнатуры сервисов с DTO (задача #7), а не OpenAPI.
Каждый работает со своим Claude Code в своих файлах, поэтому конфликтов почти нет.

| | **A — «Платформа и качество»** (Никита) | **B — «Учебная логика»** | **C — «Интерфейс и продукт»** |
|---|---|---|---|
| Суть | Всё запускается, защищено, выдерживает нагрузку, и это доказано тестами | Предметная логика деканата: модели, сервисы, формы, фоновые задачи | Всё, что видит и трогает пользователь, и история для жюри |
| Владеет кодом | `config/`, `apps/core/`, `apps/accounts/`, `apps/adminpanel/` (+ шаблоны), `tests/authz/`, `tests/e2e/`, `infra/`, `Dockerfile`, `.github/`, `.claude/`, `load/` | `apps/org/`; в `schedule`, `courses`, `assignments`, `grades`, `requests`, `notifications` — models, managers, services, selectors, forms, tasks; `apps/seed/`; `templates/certificates/` | В тех же приложениях — `views.py`, `urls.py`; `templates/` (кроме `adminpanel/`, `certificates/`), `templates/ui/`, `static/`; логотип, тексты, PDF и видео |
| Документы для PDF | Безопасность, инфраструктура, тесты, нагрузка, CI | Модель данных, сервисный контракт, бизнес-логика | Проблема и опрос, дизайн «до/после», ИИ-инструменты, **сборка PDF**, видео |
| Ревьюит у других | Все PR на права и безопасность | Views C — вызовы сервисов без обхода селекторов | UI админки у A, тексты ошибок в формах B |

Если навыки другие, B и C меняются местами целиком. A остаётся за тобой: тестирование, безопасность и пайплайн — твоя профессия.

## 4. Трекер

- **Excel** (`tracker/`):
  - общий — дашборд, этапы, функционал, блокеры, Гант;
  - личные — мои задачи, блокеры с планом Б, план по дням.

  Статусы правятся в личных файлах, общий пересобирается командой. Подробности — в `tracker/README.md`.
- **GitHub Projects** — для PR и обсуждений:
  - issue = строка бэклога;
  - ветка `<owner>/<id>-<кратко>` (например `b/43-reschedule`);
  - коммит в стиле `feat(schedule): перенос пары с проверкой конфликтов (#43)`;
  - PR закрывает issue.
- Если меняется план, правится `tracker/tracker_data.py` и выполняются две команды:
  - `build_trackers.py --personal` — пересобрать Excel, статусы сохранятся;
  - `build_pages.py` — пересобрать бэклог и личные планы.

### Цикл одной задачи
1. Issue → Claude пишет `docs/tz/<этап>_<задача>_tz.md`: цель, границы, отвергнутые варианты. Человек правит.
2. Claude пишет план с разделом «Что этот этап НЕ меняет». Человек проверяет, не разрослась ли задача.
3. Реализация по плану, тесты, `make lint test`.
4. `security-reviewer` по диффу → исправления → PR → ревью напарника.
5. В `docs/prompts.md` записываются ключевой промпт и **что пришлось возвращать на доработку**.

## 6. Риски

| Риск | Вероятность | Что делаем |

| Разрастание функций, ядро не доделано | Высокая | MoSCoW, ядро в S2 раньше «вау», заморозка 19.11, черновая отправка 8.11 |
| ИИ пишет view или HTMX-фрагмент без проверки прав | Высокая | `LoginRequiredMiddleware` по умолчанию, тест-сторож, матрица с HTMX-вариантом, `security-reviewer`, merge блокируется |
| C ждёт сервисы B | Средняя | Контракт с заглушками в S0 (#7), вёрстка на данных сидера |
| Кастомный User забыли в первой миграции | Средняя | Задача #3 A, первым коммитом; проверка в ревью |
| Участник выпал на 2–3 дня | Средняя | Зона описана в своём `CLAUDE.md`, задачи мелкие, другой подхватывает со своим Claude |
| Django медленнее, чем ожидали, на 300 RPS | Средняя | Кэш фрагментов по группам, `stress`-прогон уже в S3, подбор воркеров; запас — вертикальное масштабирование |

| Docker на Windows: переводы строк, WSL | Средняя | `.gitattributes eol=lf`, Docker Desktop + WSL2, всё через `make` / compose |
