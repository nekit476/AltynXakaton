# 01. Продукт: проблема, роли, функционал

## 1. Какую проблему решаем

Учебная жизнь студента разбросана по нескольким системам:

- ЛК студента: успеваемость, заявки, расписание, новости;
- LMS на Moodle: курсы, методички, сдача ДЗ;
- чаты и почта: переносы и объявления.

Ни одна из них не отвечает на два главных вопроса студента:
**«что у меня сегодня»** и **«как у меня дела и что надо сделать, чтобы закрыть сессию»**.

### Разбор текущего ЛК по скриншотам

Этот раздел войдёт в PDF как аргумент для критерия «Проработанность».

| Где | Что видим | Почему это плохо | Что делаем мы |
|---|---|---|---|
| Боковое меню | ~25 пунктов одним списком: «События», «Флюорография», «Вакцинация», «Реквизиты счёта», «Расписание» и т.д. | Ежедневное (расписание, оценки) тонет среди редкого (флюорография раз в год). С телефона такое меню — бесконечная прокрутка. | 4 главные вкладки (Сегодня, Расписание, Учёба, Заявки) и «Ещё». Редкое уходит в «Ещё» и в поиск. |
| Меню | Есть и «Заявления», и «Заявки», а также «Уведомления» и «Уведомления и объяснительные». | Непонятно, куда идти. Дубли по смыслу. | Один раздел «Заявки и справки» с каталогом по категориям. |
| Успеваемость | «Сдано • _ / 0 · Долг 2 • 30 · Впереди 2 • 30» | Цифры без подписей. Не видно ни итога, ни прогноза, ни того, что делать. | Прогресс-бар до зачёта или оценки, «долги» красным со сроками, кнопка «Что сделать, чтобы закрыть». |
| Заявки | Таблица, у всех статус «Напечатана», в колонке действий «Недоступно», поверх висит спиннер. | Не сказано, где и когда забрать. Таблица не помещается на телефон. | Карточки со шкалой статусов. «Готова: каб. 123, до 25.11» или сразу PDF с QR. |
| Moodle, список курсов | «Оптимизация… 2026/2027-осенний АТ-23-01 id133380» | Технический мусор в названии. Курсы живут отдельно от ЛК. | Предметы семестра прямо в кабинете, с чистыми названиями и прогрессом. |
| Moodle, страница курса | Разделы «Общее», «ЛР 1» с методичкой, загрузкой отчёта и вопросами к защите. | Структура полезная, но дедлайн, статус сдачи и оценка разбросаны. | Берём эту структуру разделов, а к каждому ДЗ добавляем дедлайн, статус и оценку. |

### Мини-исследование (C, до 6.11)

Опрос однокурсников в Яндекс Формах: 8–10 вопросов, цель — 25+ ответов.
- Чем пользуешься чаще всего? Откуда узнаёшь о переносах?
- Что бесит в текущем ЛК? Сколько раз за семестр ходишь в деканат за справкой?
- Нужны ли уведомления в Telegram?

Итоги (цифры и цитаты) пойдут в PDF и подтвердят выбор разделов.

## 2. Роли

| Роль | Что может | Чего НЕ может |
|---|---|---|
| **Студент** | Своё расписание, предметы, материалы, сдача ДЗ, свои оценки, учебный план, заявки и справки, уведомления, профиль. | Видеть чужие оценки, заявки, сдачи и профили, даже подставив адрес. |
| **Преподаватель** | Свои курсы и группы. Разделы и материалы, ДЗ и дедлайны, политика опозданий, проверка и оценки, перенос своих пар, объявления своим группам. | Чужие курсы, оценки по чужим дисциплинам, перенос чужих пар. |
| **Администратор** | Всё: пользователи, роли, группы, импорт, очередь заявок, шаблоны справок, статистика, журнал аудита, системные метрики. | Видеть пароли: хранятся только хеши. Действовать незаметно: каждое его действие пишется в аудит. |
| *(опция)* **Сотрудник деканата** | Очередь заявок и справок, новости. Подмножество прав админа. | Статистика, роли, системные настройки. |

Права задаются **разрешениями** (`schedule.reschedule`, `requests.process`, …),
а роль — это набор разрешений. Поэтому роль «деканат» добавляется одной строкой, без переписывания кода.

## 3. Полный функционал (MoSCoW)

**M** — без этого работа не засчитывается или не закрывает ТЗ конкурса.
**S** — сильно поднимает оценку. **C** — если хватит времени. **W** — сознательно не делаем.

### 3.1. Вход и профиль
| | Функция |
|---|---|
| M | Вход по логину и паролю, выход, «выйти на всех устройствах» |
| M | Профиль: ФИО, факультет, направление, курс, группа, форма и основа обучения, номер зачётки (вымышленный) |
| M | Тестовые аккаунты: 2+ студента (отличник и студент с долгами), преподаватель, админ |
| S | Смена пароля, список активных сеансов |
| C | 2FA (TOTP) для админа и преподавателя |

### 3.2. Расписание
| | Функция |
|---|---|
| M | Сегодня и неделя: время, предмет, тип (лекция/практика/лаба), аудитория, преподаватель |
| M | Переносы и отмены заметно выделены: бейдж, зачёркнутое старое время, причина |
| S | Чётная и нечётная неделя, переключение недель, «сейчас идёт / следующая пара через 15 мин» |
| S | Подписка на календарь (ICS-ссылка с секретным токеном) для Google/Яндекс/Apple Calendar |
| S | Офлайн: последнее расписание доступно без сети (PWA-кэш) |
| C | Импорт структуры из открытого расписания вуза. Аудитории, пары и дисциплины берём настоящие, **ФИО преподавателей заменяем вымышленными**. |

### 3.3. Учёба: предметы семестра
| | Функция |
|---|---|
| M | Список предметов текущего семестра с прогрессом и ближайшим дедлайном |
| M | Страница предмета с **вкладками-разделами**, которые создаёт преподаватель: «Рекомендованная литература», «ДЗ 1», «ДЗ 2», «Лабы», «Объявления»… |
| M | Раздел-задание: описание, файлы методички, дедлайн, место для загрузки, статус («не сдано / сдано / проверено / на доработку»), оценка и комментарий |
| M | Загрузка ДЗ с ограничениями по типам и размеру, повторная сдача, если разрешена |
| S | Таймер до дедлайна, «сдано с опозданием на N ч», расчёт штрафа «на лету» |
| C | Индивидуальное продление дедлайна (преподаватель продлевает конкретному студенту) |

### 3.4. Успеваемость и учебный план
| | Функция |
|---|---|
| M | Баллы и оценки по каждой дисциплине и контрольной точке, итог семестра, зачёты и экзамены |
| M | «Как у меня дела»: общий статус (всё ок / есть долги), список долгов со сроками |
| M | Сессия: даты экзаменов и зачётов, результаты |
| S | **Учебный план**: все семестры, дисциплины, часы, форма контроля, ЗЕ. Пройденное отмечено. |
| S | **«Что нужно до зачёта / автомата»**: сколько баллов не хватает и какие работы их дают |
| C | История по семестрам, средний балл, график |

Пороги оценок (например, 61/76/91 из 100) хранятся в настройках,
а не в коде: в разных вузах и на разных кафедрах они свои.

### 3.5. Заявки и справки
| | Функция |
|---|---|
| M | Каталог справок и заявлений: об обучении, в налоговую, в соцзащиту, по месту работы родителей, о периоде обучения с оценками, заявление на перезачёт и т.д. |
| M | **Автозаполнение:** ФИО, факультет, направление, курс, группа, форма и основа подставляются из профиля. Студент выбирает только «куда» и «сколько». |
| M | Статус заявки со шкалой: Подана → В работе → Готова → Выдана (или Отклонена с причиной) |
| S | **Электронная справка мгновенно:** PDF с QR-кодом и страницей проверки подлинности `/verify/<код>` без очереди. Водяной знак «КОНЦЕПТ, НЕ ЯВЛЯЕТСЯ ДОКУМЕНТОМ». |
| S | Бумажная: «Готова, забрать в каб. 123 до 25.11» плюс уведомление |
| M | Админ или деканат: очередь заявок, смена статуса, комментарий, вложение |

### 3.6. Уведомления и новости
| | Функция |
|---|---|
| M | Центр уведомлений (непрочитанные, «прочитать все»), новости и объявления деканата |
| M | Напоминания о дедлайнах: за 72 ч, 24 ч и 3 ч, только тем, кто ещё не сдал |
| M | Уведомления об изменениях: перенос пары, новая оценка, готова справка, изменён дедлайн |
| S | Адресность новостей: всем / факультету / курсу / группе |
| C | Telegram-бот: привязка по одноразовому коду, дублирование важных уведомлений |
| C | Web Push через PWA |

### 3.7. Преподаватель
| | Функция |
|---|---|
| M | Мои курсы и группы |
| M | **Конструктор разделов:** создать, переименовать, переставить, скрыть вкладку. Типы: материалы, задание, объявление. |
| M | **ДЗ:** описание, файлы, макс. балл, дедлайн, допустимые форматы и размер, число попыток |
| M | **Политика опоздания** (выбирает преподаватель): ① не принимать после дедлайна; ② принимать с пометкой «опоздание»; ③ штраф X % за сутки до «жёсткого» дедлайна; ④ при несдаче автоматически 0 и долг |
| M | **Изменение дедлайна** с историей и уведомлением студентов |
| M | **Перенос пары:** выбрать занятие → новая дата, пара, аудитория → **проверка конфликтов** (аудитория, группа, преподаватель заняты) → уведомление группе |
| S | При конфликте 3 ближайших свободных варианта |
| M | Проверка сдач: список, скачать, оценить, вернуть на доработку с комментарием |
| S | Ведомость (журнал баллов) по группе, экспорт в CSV/XLSX |

### 3.8. Администратор
| | Функция |
|---|---|
| M | Пользователи: создать, заблокировать, сбросить пароль, назначить роль. Группы, факультеты. |
| M | Очередь заявок (если нет роли «деканат»), шаблоны справок |
| M | **Статистика:** активные пользователи (день/неделя), заявки по статусам и срокам обработки, доля сданных ДЗ в срок, распределение оценок, топ долгов по дисциплинам |
| S | Журнал аудита: кто, что, когда изменил (оценки, переносы, роли, входы) |
| S | Системная панель: ссылка на Grafana (RPS, ошибки, задержки, ресурсы) |
| C | Импорт пользователей и групп из CSV |

### 3.9. Сквозное
| | Функция |
|---|---|
| M | Мобильная версия от 360 px, нижняя панель вкладок на телефоне и боковая на ПК |
| M | Плашка «Концепт для конкурса, не официальный сервис», свой логотип, `noindex` |
| M | Пустые состояния («Заявок пока нет — закажи первую справку»), ошибки, скелетоны загрузки |
| S | Экран **«Сегодня»**: следующая пара, изменения, горящие дедлайны, новые оценки, статусы заявок |
| S | Глобальный поиск (Ctrl+K или иконка): предметы, материалы, справки, разделы меню |
| S | Тёмная тема, PWA (установка на главный экран) |
| C | ИИ-помощник «спроси деканат» по FAQ. Ключ только на сервере, ассистент ничего не меняет в данных. |
| W | Реальные интеграции с системами вуза, платежи, чат между студентами, нативные приложения |

## 4. Карта экранов

```
Студент (мобильная нижняя панель: Сегодня · Расписание · Учёба · Заявки · Ещё)
├─ Сегодня ............ следующая пара, изменения, дедлайны, оценки, заявки
├─ Расписание ......... день / неделя, переносы, ICS
├─ Учёба
│  ├─ Предметы ........ список → страница предмета → вкладки-разделы → ДЗ (сдача)
│  ├─ Успеваемость .... по дисциплинам, долги, «что нужно до зачёта», сессия
│  └─ Учебный план .... по семестрам
├─ Заявки ............. каталог → форма с автозаполнением → статус / PDF
└─ Ещё ................ уведомления, новости, профиль, настройки, о проекте

Преподаватель: Сегодня · Расписание (перенос) · Курсы (конструктор, ДЗ, проверка, ведомость) · Объявления
Админ: Обзор (статистика) · Пользователи · Заявки · Справки (шаблоны) · Аудит · Система
```

## 5. Пять сквозных сценариев для демо и E2E

1. Студент входит с телефона → «Сегодня» → видит перенос пары → открывает неделю.
2. Студент открывает предмет → вкладку «ДЗ 2» → загружает отчёт → статус «сдано».
3. Преподаватель меняет дедлайн и переносит пару (ловит конфликт, выбирает предложенный слот) → студент получает уведомления.
4. Студент заказывает справку → поля уже заполнены → получает PDF с QR → проверка по QR.
5. Второй студент пытается открыть заявку первого по прямой ссылке → 404. Админ видит обе заявки и статистику.
