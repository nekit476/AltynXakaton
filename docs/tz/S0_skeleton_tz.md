# ТЗ. Этап `S0_skeleton`: каркас проекта, окружение, БД в Docker

Задачи бэклога: #3 (Django-проект, кастомный User, compose, pre-commit), частично #2 (CLAUDE.md по модулям).

## Цель

Любой участник одной командой получает рабочее окружение: Python 3.13, все зависимости в `.venv`, свой `.env`.
Django-проект запускается на localhost, своя модель пользователя лежит в первой миграции.
Код разделён на четыре модуля — по одному на участника плюс тесты. База данных поднимается в Docker и подключается как удалённая: переезд на сервер не потребует правок кода.

## Требования к реализации

1. Одна команда на Windows (`scripts/setup.ps1`) и на Linux/macOS (`scripts/setup.sh`): ставит uv, если его нет, выполняет `uv sync --locked` и bootstrap.
2. Повторный запуск безопасен: существующий `.env` не перезаписывается.
3. Версия Python закреплена (`.python-version`), версии пакетов — `uv.lock`.
4. Четыре модуля: `core/` (A), `domain/` (B), `web/` (C), `tests/`. Каждый Django-пакет подключён в `INSTALLED_APPS`.
5. Границы проверяются тестом: `domain` не импортирует `web`, `web` не импортирует модели и менеджеры `domain`.
6. `AUTH_USER_MODEL = "users.User"` с первой миграции: UUID-ключ, роль (по умолчанию «студент»), отчество, ФИО в русском порядке.
7. БД подключается только через `DATABASE_URL`. Параметры из query попадают в `OPTIONS`, таймаут подключения задан по умолчанию, соединения постоянные с проверкой. Не-PostgreSQL отвергается.
8. Сервер БД общий, база у каждого участника своя. Тестовые базы не пересекаются.
9. Redis необязателен: без него кэш в памяти, Celery в eager-режиме. Тесты общий Redis не трогают.
10. `/health/` без обращения к БД. `/ready/` проверяет БД и кэш и называет упавший компонент, но не раскрывает текст ошибки. Оба адреса публичны и не кэшируются.
11. Docker: один образ для web, worker и beat, не от root. В compose порты слушают `127.0.0.1`. При первом запуске создаются базы участников.
12. Команды разработки работают одинаково на Windows и Linux.
13. `uv run poe test`, `uv run poe lint` и `uv run poe check` проходят без замечаний.

## Принятое решение и отвергнутые варианты

| Вопрос | Выбрано | Отвергнуто и почему |
|---|---|---|
| Окружение | **uv** + `uv.lock` | `venv` + `pip` + `requirements.txt`: нет лока с хешами, Python 3.13 каждый ставит руками (у Никиты стоит 3.11 из Microsoft Store). Poetry медленнее и не ставит сам Python. |
| Запуск команд | **poethepoet**, задачи в `pyproject.toml` | Makefile: make на Windows из коробки нет. Пара `.ps1` + `.sh` на каждую команду — двойная поддержка. |
| Скрипт установки | `setup.ps1` / `setup.sh` → `bootstrap.py` | Вся логика в PowerShell: дублировалась бы в sh. Python-логика одна, а оболочки только ставят uv. `setup.ps1` написан на ASCII, потому что PowerShell 5.1 читает файл без BOM как ANSI. |
| Разделение кода | Модули по участникам: `core` / `domain` / `web` / `tests` | `apps/<app>/` из плана, где B и C работают в одной папке: больше конфликтов при слиянии, а граница контракта видна только на ревью. |
| Общая БД | Один сервер, **база на участника** | Одна общая база: миграции из незаконченной ветки ломают базу коллег, тестовые `test_dekanat` пересекаются. Локальный PostgreSQL у каждого: прямо противоречит постановке задачи. SQLite для разработки: модели B с JSONB и массивами на ней не мигрируют. |
| Доступ к удалённой БД | SSH-туннель, `DATABASE_URL` не меняется | Открытый порт PostgreSQL в интернет: противоречит 03_security.md §8. Прямой TLS оставлен как опция через `?sslmode=require`. |
| Порт Docker-PostgreSQL | **5433** | 5432: занят системной службой `postgresql-x64-17` у Никиты. |
| Ключ пользователя | UUID | Счётчик: id виден в URL `/a/users/<id>/`, и людей можно перебрать. |
| Миграции на локальном стенде | Перед стартом web | Отдельный одноразовый сервис `migrate`: поведение `up --wait` с завершившимися контейнерами зависит от версии compose. |

## Требования к тестам

1. `User`: модель проекта, роль по умолчанию, суперпользователь получает роль админа, UUID, порядок ФИО.
2. `/health/` и `/ready/`: коды ответа, упавший компонент, отсутствие утечки текста ошибки, публичность, `no-store`.
3. Сборка настроек: хост, порт и база из URL, `sslmode`, таймаут, постоянные соединения, отказ от не-PostgreSQL, кэш с Redis и без него.
4. Bootstrap: `.env` для каждого участника из настоящего `.env.example`, подставляется только нужное, пустой Redis сохраняется, шаблон без ключа отвергается.
5. Архитектура: все приложения подключены, запретов на импорт нет, сторож ловит нарушения на подложенных файлах.
6. Главная собрана на `base.html`, плашка «Концепт» и `noindex` на месте.
