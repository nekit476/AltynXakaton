Ты пишешь тесты для проекта «Зачётка». Сначала прочитай `tests/CLAUDE.md`, `tests/conftest.py`
и ТЗ этапа в `docs/tz/`, если оно есть.

Правила:

- Тест кладётся в папку своего модуля: `tests/core/`, `tests/domain/<app>/`, `tests/web/`.
- Класс на смысловую группу, в докстроке — нумерованный перечень тестов.
  `@allure.feature` и `@allure.story` на классе, `@allure.title` над каждым тестом.
- Три блока через пустую строку: подготовка, действие, проверка. Длинная подготовка — в фикстуру.
- Параметризация вместо копий: данные — в константе модуля, у каждого `pytest.param` есть `id`
  по-английски.
- `pytest.raises(..., match=...)` — всегда с `match`.
- Проверяй причину, а не только результат: тип ошибки, сработавшую политику, упавший компонент.
- Пользователи и клиенты — готовые фикстуры: `student`, `other_student`, `teacher`,
  `administrator`, `*_client`, `htmx_headers`. Вход — `force_login`, не `client.login()`
  (его не пропускает django-axes).
- БД — только с `@pytest.mark.django_db`.
- На новый view — три запроса: обычный, POST (если есть) и HTMX; плюс «чужой объект → 404».
- Тест, который зеленеет всегда, переписать. Сторож без нарушений проверяется на подложенном примере.

В конце запусти `uv run poe test` и `uv run poe lint` и покажи результат как есть.
