---
name: db-migration
description: Изменить модели и создать миграцию безопасно для общей БД команды. Использовать при любой правке models.py.
---

1. Правишь модели только своего модуля (`domain/<app>/` у B, `core/` у A).
2. `uv run poe makemigrations` → прочитай созданный файл: нет ли удаления столбца с данными,
   нет ли переименования, которое Django понял как «удалить + создать».
3. Миграция обратима: для `RunPython` есть `reverse_code`.
4. `uv run poe migrate` — на **своей** базе (`dekanat_<буква>`), не на чужой.
5. Откат проверяется: `uv run python manage.py migrate <app> <предыдущая>` и снова вперёд.
6. `uv run poe check` — `makemigrations --check` не должен находить забытых изменений.
7. Две миграции одного приложения в разных ветках — договоритесь, кто вливает первым;
   второй делает `makemigrations --merge` после обновления от main.
